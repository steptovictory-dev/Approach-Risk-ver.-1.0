# Подготовка признаков

Ноутбук 06 переименован в `06_time_split.ipynb`, заголовок —
«Признаки и разделение по времени». Скрипт сборки и README используют новое имя.

Ноутбук 07 выполнен: словари airport / typecode / icaoaircrafttype / AC_CLASS
и параметры стандартизации lat / lon рассчитаны исключительно на train.
UTC-преобразование времени суток и дня недели реализовано с проверкой.
Сырые поля не перезаписаны; данные и локальная split-разметка неизменны по SHA256.

В test 23 297 записей без typecode (4,262%); 28 с unseen typecode (0,0051%).
icaoaircrafttype отсутствует в 29 780 (5,448%); unseen кодов нет.
AC_CLASS и airport физически заполнены и не имеют unseen категорий.
Missing и unseen различаются, обучающие значения сохраняют исходные строки.
Индекс категории не используется как порядковый числовой признак.

Все значения lat / lon конечны и проходят диагностические географические
границы. Bearing конечен и лежит в [0,360) во всех рабочих частях; это не
подтверждает его единицы или направление. Историческая доступность не доказана.

Основное сравнение уточнено: geometry против geometry_aircraft без bearing и
AC_CLASS. Их условные варианты остаются отдельно до подтверждения семантики.
AC_CLASS не расшифрован автоматически; ZZ сохранен как сырой код.

План оценки сохранен в preparation_plan.json: AP основная метрика, ROC-AUC,
Brier и калибровка дополнительно; baseline из частоты train; логистическая
регрессия с L2 и сеткой C=[0.01,0.1,1,10], выбор AP на validation, при равенстве
меньший C. Порог выбирается по F1 validation, при равенстве более высокий.
Без автоматического class_weight и refit на train+validation. Парный bootstrap
по неделям test (1000, seed42) запланирован, не выполнен. Выбор недель не
доказывает достаточную независимость. Основной GoA-классификатор не обучался,
test-метрики не вычислялись. Следующий шаг — первый ограниченный baseline только
после явного решения проводить ретроспективное моделирование с этими ограничениями.
