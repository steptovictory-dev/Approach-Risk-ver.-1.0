# Кандидатные решения перед моделированием

## Признаки

Два набора: C40_core (airport, C40_BEARING, C40_CROSS_LAT, C40_CROSS_LON)
и C40_aircraft (те же поля + исходные typecode, icaoaircrafttype, AC_CLASS).
Календарные преобразования времени C40 пока только запланированы.
market_segment исключен из кандидатных наборов из-за календарного провала;
восстановленные описания самолетов не используются. Пропуски сохраняют запись.
Историческое время получения всех кандидатных полей остается неподтвержденным.
Словарь AC_CLASS и единицы / семантика bearing требуют проверки до кодирования.

Это локальный кандидат разделения, а не новая версия очищенной базы A.
Зазор 24 часа не доказывает независимость событий. Время публикации меток
не записано; purge использует время зарегистрированных событий, не получения.
Validation заканчивается по наблюдаемому C40 20 декабря 2022; test — 30 мая 2023.
Календарную полноту нельзя предполагать по названию года.

## Повторы и область применимости

flight_id: 42 202 строки входят в повторные группы; 13 005 идентификаторов
встречаются в нескольких рабочих частях. Точный составной ключ
flight_id + icao24 + airport + landing_time уникален во всей финальной базе.
Прокси события icao24 + airport + первый attempt также уникален; межпериодных
пересечений по нему нет. Это проверка конкретных полей, не независимая
идентификация физического рейса.

В test 545 994 из 546 577 строк относятся к ранее встречавшимся самолетам.
Результат будущего моделирования будет характеризовать преимущественно
будущие события знакомого парка. Идентификаторы не должны входить в признаки.
Для нового парка нужна отдельная проверка, не замена календарного test.
EGCC имеет 87 435 строк / 306 GoA только в train; validation и test его
не содержат. Нельзя распространять test-метрики на EGCC или автоматически
объявлять покрытие всех исходных аэропортов. Доли аэропортов заметно меняются.

## Что остается до обучения

Зафиксировать ретроспективный статус при отсутствии исторических received_at,
проверить словарь кодов и правила UTC-преобразований, определить обработку
missing / unseen с fit только на train. План оценки в ноутбуке 06 пока не исполнен.
Модель не обучалась, test не использовался для подбора признаков по метрикам.
Новые данные и исходные метки не изменялись. Результаты 05–06 после коммита
39f706d пока не закоммичены.
