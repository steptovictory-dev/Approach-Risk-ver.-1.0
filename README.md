# Approach Risk ML

Проект по анализу табличных данных о посадках и уходах на второй круг.
На первом этапе проверяем качество данных и готовим воспроизводимый baseline
классификации исхода захода.

## Текущий результат

Выполнен первичный технический аудит `go_arounds_augmented.csv.gz`:

- 8 969 145 строк, 31 поле, 176 аэропортов;
- 33 664 записи с `has_ga=True` – около 0,375%;
- полных дублей и совпадений проверяемого ключа `time + icao24 + airport` не найдено;
- в `wind_gust_knts` отсутствует 92,15% значений;
- проверены даты, пропуски, базовые диапазоны и распределения по аэропортам и месяцам.

Код, сохраненные результаты и вывод находятся в
[`notebooks/01_initial_data_audit.ipynb`](notebooks/01_initial_data_audit.ipynb).
Остальные пять файлов пока только инвентаризированы. Модели еще не обучались.

## Запуск аудита

Аудит выполнен с Python 3.14.6 и pandas 3.0.6.

1. Создайте окружение Python и установите зависимости:
   `python -m pip install -r requirements.txt`.
2. Откройте ноутбук в Jupyter или VS Code с поддержкой Jupyter.
3. Выберите ядро установленного окружения и выполните ячейки по порядку.

Рабочая папка ядра должна быть корнем проекта или папкой `notebooks`.
Полный CSV содержит почти 9 млн строк; загрузка и проверки требуют нескольких
гигабайт свободной оперативной памяти. Данные в ходе аудита не изменяются.

## Ограничения постановки

`has_ga` обозначает наличие ухода на второй круг. Эта метка не определяет
опасность захода, причину маневра или вероятность аварии.

Доступность полей до исхода еще требует проверки по описанию источника.
Пока рассматривается ретроспективная классификация, а не ранний прогноз.
`n_approaches` и `n_rwy_approached` исключаются из первого набора входных
признаков как потенциальная утечка информации об исходе.
