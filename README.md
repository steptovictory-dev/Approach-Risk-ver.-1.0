# Approach Risk ver. 1.0

**Проект закрыт в текущем исследовательском объеме 11 октября 2026 года.** Развитие продолжается в Approach Risk ver. 1.1. Ссылка на новый GitHub-репозиторий будет добавлена после публикации.

Approach Risk 1.0 – воспроизводимое исследование авиационных данных, восстановления траекторий и прогнозирования ухода на второй круг (GoA). От проверки источников перешли к подготовке выборки, обучению моделей и измерению их возможностей. Результаты помогли сформулировать следующий вопрос: как развивается риск непосредственно во время конечного захода? Это последовательное развитие исследования: каждый этап уточняет следующий.

## Проверенная основа данных

Европейский Parquet из Zenodo 10210178: **7 984 254 записи, 20 аэропортов, 26 253 метки GoA**, фактический период 01.01.2019–30.05.2023 UTC. MD5 сверена с источником.

Подготовка стала полноценным исследованием качества. Нормализованы точные пустые строки, обогащены сведения о самолетах, разобраны многократные попытки, неполные C40 и нестандартные профили. Исходный файл сохранен неизменным. Исключенные записи сохранены отдельно; решения, версии, значения и порядок оставшихся строк проверены. Диагностические флаги не превращались автоматически в правила удаления.

Итог этапа 06: **6 331 485 записей / 18 349 GoA** в `europe/data/analytical/06_05_cases_excluded.parquet`. Это документированный отбор (не массовое исправление подозрительных значений). `flight_id` не уникален; использованы составные ключи. Совпадение GoA с `n_attempts > 1` подтверждает согласованность полей, но не независимую достоверность всех уходов.

Подготовленные данные и проверки **будут использоваться в Approach Risk ver. 1.1** с сохранением происхождения и повторной проверкой пригодности. Таблица C40 не заменяет последовательные наблюдения конечного захода; их потребуется проверить и/или дополнительно получить.

## Что обучали и какие результаты получили

### Восстановление траекторий

Обучались Ridge-поправки к интерполяции с разделением по рейсам и проверками на других датах. После первоначального улучшения линейного метода сравнение с более сильным baseline уточнило выбор.

Финальная проверка: **15 рейсов / 28 511 задач**, две новые даты; средняя рейсовая ошибка:

| Метод | Ошибка |
|---|---:|
| Модель этапа 11: линейная интерполяция + ML-поправка | 118,43 м |
| Кубический Эрмит | **105,34 м** |
| Эрмит + Ridge | 105,71 м |

Оставлен Эрмит: обучаемая поправка не улучшила его в проверенных условиях. Восстановление внутренних точек использует оба конца интервала и не является прогнозом в реальном времени. [Итог](research/c40_geometry/notes/research_conclusion.md).

### Классификация GoA на C40

Обучение с учителем: **логистическая регрессия L2** и **CatBoost**. Train 2019–2021: **4 165 060 / 11 626 GoA**; validation 2022: **1 619 848 / 4 984**; test – наблюдаемая часть 2023: **546 577 / 1 739**. Преобразования оценивались на train; конфигурации и пороги выбирались на validation. Для CatBoost обучено десять кандидатов по 500 деревьев.

| Модель | Признаки | Average precision (AP) | ROC-AUC |
|---|---|---:|---:|
| Logistic | Без погоды | 0,003989 | 0,5682 |
| Logistic | С погодой | 0,006679 | 0,6084 |
| CatBoost | Без погоды | 0,004361 | 0,5711 |
| CatBoost | С погодой | **0,006812** | **0,6237** |

Доля GoA на test – **0,3182%**. Погода улучшила ранжирование в обеих выбранных парах. Разность AP погодной и непогодной пары CatBoost: **0,002451**, дневной парный bootstrap-интервал 95% **[0,001304; 0,003992]**, условный на выбранных моделях. Прирост AP погодного CatBoost относительно погодной Logistic – около **1,99%**; значимость различий семейств отдельно не проверялась.

При пороге для validation FPR ≤ 1% погодный CatBoost обнаружил на test **6,73% GoA**, с **FPR 1,31%** и precision **1,61%**. Измеренное улучшение пока недостаточно для эксплуатационной системы предупреждений. Test ранее просматривался; независимый подтверждающий период отсутствует. [Logistic: результат](research/weather-model-comparison/reports/07_baseline_research_answer.md), [CatBoost: результат](research/boosting-weather-comparison/reports/08_research_answer.md).

### Погода и покрытие

При давности 60 минут и задержке 15 минут погодное покрытие – **99,8594%**. Переход к нулевой задержке изменил проверяемую информацию у **48,88% событий**, почти не изменив покрытие. Историческое фактическое время получения сообщений неизвестно. [Результат](research/metar-quality-and-availability/reports/06_research_answer.md).

Покрытие GoA фиксированными прогнозами относительно исходного наблюдаемого test-периода составило **61,89%**. Положительные события вне покрытия отделены от ошибок модели: метрики внутри выборки нельзя переносить на все посадки. [Анализ знаменателя](research/sample-selection/reports/selection_evaluation_findings.md).

## Версия 1.1

Версия 1.0 дала проверенные данные, инструменты и измеренную границу возможностей признаков на C40. Следующий шаг – приблизить задачу к работе диспетчера: наблюдать динамику конкретного захода, прогнозировать отклонения и объяснять риск.

В **Approach Risk ver. 1.1** планируется мониторинг от определяемого начала следования глиссаде до условной контрольной высоты **300 ft над уровнем аэродрома** первого эксперимента. Начальный аэропорт – **LFPG, Шарль-де-Голль**. Предполагаются прогноз при сохранении текущей динамики, история отклонений, уровень риска и короткая причина.



## Воспроизведение и структура

Ноутбуки, протоколы, отчеты, графики и команды находятся в тематических папках. Дополнительно сохранен [исторический эксперимент 2019 года](archive/2019_experiment/README.md). Два суточных глобальных архива ADSB.lol за 2025–2026 проверены как пилот источника; готовая размеченная выборка США не построена.

Для нового окружения Python ≥ 3.11:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install -e ".[boosting]"
```

Полное воспроизведение требует локальных данных и настроенного реестра; проверки сохраненных прогнозов также требуют моделей. Сырые данные, модели, локальные статьи, PDF и чекпоинты исключены из Git. Git-клон не заменяет резервную копию. Для просмотра результатов достаточно сохраненных отчетов; повторное обучение не требуется.
