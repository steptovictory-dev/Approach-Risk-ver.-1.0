## Запуск

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe europe/scripts/profile_data.py
```

В Jupyter открыть `notebooks/01_database_audit.ipynb` и выбрать окружение проекта `.venv`. Ноутбук находит корень из папки проекта, `europe` или `europe/notebooks`. Первая диагностическая ячейка запускает полный аудит и заново формирует отчеты. Исходный Parquet проверяется по SHA256 до и после выполнения.

Для программного выполнения ноутбука:

```powershell
.\.venv\Scripts\python.exe europe/scripts/execute_notebook.py
```

Каждая таблица аудита выводится отдельной ячейкой. Ноутбук 02 показывает географический состав, покрытие по аэропортам и месяцам, частоты отмеченных уходов, пропуски, число попыток, типы самолетов и диагностические группы. Интервалы Уилсона 95% рассчитаны при условной независимости записей. Повторные борта и неоднородность выборки требуют отдельного анализа.

Для программного выполнения 02:

```powershell
.\.venv\Scripts\python.exe europe/scripts/execute_visualization.py
```

Первая ячейка пересчитывает дополнительные агрегаты по исходному Parquet и проверяет его SHA256 до и после прохода. Агрегаты аудита 01 используются как входные отчеты. Графики сохраняются в `figures/` в PNG и SVG. [Исследовательские наблюдения](reports/visualization/research_observations.md) фиксируют вопросы для диссертации и возможной публикации.

Очистка по доступности C40 завершена в 04_10. Ноутбуки 01 и 02 описывают исходную базу; их счетчики относятся к данным до очистки.

В ноутбуке 03 выполнены согласованная нормализация пустых строк и справочное обогащение типов самолетов. Шаг 7 содержит [полную временную диагностику C40](reports/preparation/06_c40_review.md): 45 записей после первой попытки, но до посадки, и 42 записи после посадки рассматриваются отдельно. Для запуска только этого шага:

```powershell
.\.venv\Scripts\python.exe europe/scripts/execute_preparation.py --c40-diagnostics-only
```

На согласованном шаге 8 создана копия `data/working/03_c40_diagnostic_flags.parquet` с тремя булевыми флагами C40. Все записи и существующие поля сохранены; время и целевая метка не исправлялись. Временные флаги предназначены для аудита, а не для раннего прогноза. [Журнал проверки](reports/preparation/07_c40_flags_applied.json) содержит счетчики и SHA256. Для выполнения только шага 8:

```powershell
.\.venv\Scripts\python.exe europe/scripts/execute_preparation.py --apply-c40-flags-only
```

Шаг 9 содержит [разбор повторяющихся flight_id](reports/preparation/08_flight_id_review.md). Все 23 889 повторяющихся имен относятся к разным UTC-датам внутри каждого имени; точных дублей среди 53 127 записей не найдено. Идентификатор не используется как единственный ключ связи, строки сохранены. Для запуска только этого шага:

```powershell
.\.venv\Scripts\python.exe europe/scripts/execute_preparation.py --flight-id-diagnostics-only
```

Полный проход работает блоками по 100 000 строк. Проверка повторов использует хеши только для отбора кандидатов, после чего сравнивает точные значения ключа и всех содержательных полей. Дни без записей показывают отсутствие наблюдений в файле, а не подтвержденное отсутствие полетов.

Шаг 10 содержит [разбор нескольких попыток](reports/preparation/09_attempts_review.md): 1 052 строки с n_attempts > 2 сохранены без изменений. Согласованность времен не подтверждает назначение полета или каждую эксплуатационную метку. Запуск: `\.venv\Scripts\python.exe europe/scripts/execute_preparation.py --attempts-diagnostics-only` (из корня проекта, с префиксом `.` перед обратным слешем).

Источник, лицензия, статья и реестр исходных файлов описаны в [общем реестре](../docs/sources/README.md). Уход в разметке источника не является доказательством опасности аэропорта.


После [04_10](notebooks/04_с40/04_10_apply_c40_selection.ipynb) актуальная выборка эксперимента C40 – `data/analytical/04_c40_available.parquet`: 6 331 494 строки, 18 358 GoA=True. Неполные записи C40 и записи с C40 не раньше первой попытки сохранены отдельно в `data/analytical/04_c40_outside_experiment.parquet`. Правило ограничивает доступность точки прогноза и не удостоверяет правильность всех меток.


После [05_03](notebooks/05_aircraft_types/05_03_restore_classification.ipynb) актуальная рабочая копия – `data/analytical/05_aircraft_classification_enriched.parquet`. Добавлены справочные классификации для 21 703 строк, включая 105 GoA=True; все наблюдения и исходные поля сохранены.


После 05_04 актуальная копия – `europe/data/analytical/05_aircraft_model_names_enriched.parquet`. Еще 8 510 отсутствующих классификаций восстановлены по однозначному коду без крайних пробелов или явному обозначению модели ICAO; 18 GoA=True. Все строки и исходные поля сохранены. Новые статусы `restored_from_trimmed_designator` и `restored_from_explicit_model_name` записаны в ранее добавленные поля. Историческая идентичность и доступность признака в момент полета не подтверждены.


После 05_05 актуальная копия – `europe/data/analytical/05_aircraft_types_reviewed.parquet`, 35 полей. Суммарно восстановлено 37 940 описаний, включая 155 GoA=True. Новый статус `restored_from_reviewed_family_description` означает широкое единое Description подтвержденного подтипа или семейства, а не выбор конкретного designator. Все строки и исходные значения сохранены. Неразрешенный остаток остается неизвестным; этап ограниченного восстановления типов закрыт.
