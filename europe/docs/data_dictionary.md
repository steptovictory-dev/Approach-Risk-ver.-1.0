# Поля европейской базы данных

Источник: [Zenodo 10210178](https://zenodo.org/records/10210178), версия v1. Названия и типы проверены по локальному Parquet. Интерпретации, не раскрытые в описании источника, отмечены отдельно. Все временные поля в фактической схеме имеют UTC.

Физическая схема содержит 21 столбец: 20 содержательных полей и сохраненный индекс pandas. Погодных полей и полных траекторий в файле нет.

| Поле | Фактический тип | Смысл и ограничение |
| --- | --- | --- |
| `flight_id` | string | Идентификатор записи полета авторами. Не уникален во всем файле; алгоритм формирования требует уточнения. |
| `callsign` | string | Позывной. Не является уникальным идентификатором полета или борта. |
| `icao24` | string | 24-битный ICAO-адрес борта в шестнадцатеричной записи. Адрес сам по себе не подтверждает оператора или назначение полета. |
| `landing_time` | timestamp[ns, UTC] | Время итоговой посадки. На странице Zenodo соответствующее время названо `stop`; в фактическом файле используется `landing_time`. Для раннего прогноза это будущая информация. |
| `registration` | string | Регистрационное обозначение борта по имени поля. Источник и историческая актуальность справочного сопоставления требуют проверки. |
| `typecode` | string | Код типа самолета по имени поля. Правило заполнения и дата справочника требуют проверки. |
| `icaoaircrafttype` | string | Составной классификационный код типа воздушного судна по имени поля. Таблица кодов и алгоритм сопоставления требуют проверки. Пустая строка отличается от null. |
| `airport` | string | ICAO-код аэропорта итоговой посадки. Не описывает все предыдущие аэродромы полета. |
| `country` | string | Страна аэропорта в исходной таблице. Принята как группировка источника, без автоматического применения нормативов. |
| `attempt_times` | list<timestamp[us, UTC]> | Список времен выявленных попыток захода. Известен после завершения наблюдения; не входной признак раннего прогноза. |
| `ILS` | list<string> | По описанию авторов – обозначения ВПП при попытках захода. Имя поля не доказывает фактическое выполнение захода по ILS или соблюдение процедуры. |
| `n_attempts` | int64 | Кол-во выявленных попыток. Утечка исхода для прогноза до события; больше двух попыток не доказывает учебный полет. n_attempts - 1 не является подтвержденным числом эксплуатационных уходов. [Диагностика](../reports/preparation/09_attempts_review.md). |
| `GoA` | bool | Есть хотя бы один отмеченный уход на второй круг. Целевая метка источника; не число уходов и не оценка опасности. |
| `market_segment` | string | Сегмент перевозок из обогащения EUROCONTROL. Доступность и актуальность такого справочника до момента прогноза требуют проверки. |
| `AC_CLASS` | string | Класс воздушного судна по описанию источника. Точную таблицу кодов и правила заполнения нужно проверить. |
| `AP_C_RWY` | string | Поле обозначения ВПП в обогащении по имени поля. На странице Zenodo подробно не описано; нельзя без проверки считать его ВПП первого захода или доступным до исхода. |
| `C40_CROSS_TIME` | timestamp[ns, UTC] | Время входа в область ASMA радиусом 40 NM вокруг опорной точки аэропорта, из обогащения EUROCONTROL. Первый или последний вход – для этого файла не установлено. В 45 записях время позже первой попытки, но до последней; в 42 – после указанной посадки. Пригодность для раннего прогноза требует проверки относительно выбранного момента наблюдения. |
| `C40_BEARING` | double | Направление между самолетом и аэропортом при входе в ASMA по описанию источника. Ожидаемые градусы и диапазон [0, 360) используются только как диагностическая гипотеза. |
| `C40_CROSS_LAT` | double | Широта точки входа в ASMA. Ожидаемые градусы и допустимый диапазон [-90, 90] проверяются диагностически. Система координат отдельно не подтверждена. |
| `C40_CROSS_LON` | double | Долгота точки входа в ASMA. Ожидаемые градусы и допустимый диапазон [-180, 180] проверяются диагностически. Система координат отдельно не подтверждена. |
| `__index_level_0__` | int64 | Служебный сохраненный индекс pandas. Не считать признаком модели или уникальным идентификатором. При сравнении содержательных дублей исключается из определения равенства. |

В фактическом файле нет `n_rwy_approached`, хотя поле перечислено в описании Zenodo. Число уникальных направлений можно отдельно вычислить из `ILS`, но это будет производный показатель, известный после события.

Аудит различает null, пустую строку, строку из пробелов, текстовые маркеры отсутствия и пустой список. Эти представления не объединяются автоматически и не заменяются нулями. Категориальные таблицы обозначают физический null как `<NULL>` только для отображения.

Доступность признаков до события пока не подтверждена. Поля времени итоговой посадки, попыток и итоговых направлений исключаются из кандидатных признаков раннего прогноза. Очистка и окончательный набор признаков будут определены после аудита.

[Разбор C40, шаг 7 ноутбука 03](../reports/preparation/06_c40_review.md) разделяет временные противоречия, возможный повторный вход и пропуски. [Статья авторов, разделы 2.2–2.3](https://doi.org/10.59490/joas.2023.7219) описывает сопоставление OpenSky и EU-NM по дню, аэропорту и ICAO24. C40 не является отметкой начала ILS-захода. На шаге 7 флаги сохранены только в отчетах; на согласованном шаге 8 они добавлены в отдельную рабочую копию.

В `icaoaircrafttype` фактически смешаны форматы: `L2J`, `A332`, `a320`, `82R` и другие. Диагностика проверяет преобладающий структурный шаблон и совпадение с `typecode`; это не подтверждение ошибки. Причина и правило нормализации пока не установлены.

## Идентификатор наблюдения и повторяющиеся flight_id

[Шаг 9 ноутбука 03](../reports/preparation/08_flight_id_review.md) проверил все 23 889 повторяющихся значений flight_id, 53 127 записей. В каждой группе UTC-даты посадки различны; в 22 547 группах различаются адреса. Это коллизии имен, а не основание удаления дублей. Среди этих записей точных содержательных дублей не найдено.

Исходный flight_id не является уникальным ключом таблицы и не используется как признак модели. Для присоединения данных нужен контекст времени, аэропорта и ICAO24. Ключ `landing_time + icao24 + airport` уникален в текущем аудите, но не подтверждает идентичность физического полета. Новый служебный идентификатор пока не добавлен.

## Производные поля рабочей копии

По согласованному правилу в копии `01_empty_strings_normalized.parquet` точные пустые строки в `registration`, `typecode` и `icaoaircrafttype` заменены на null. Булевы поля `<имя>_was_empty_string` сохраняют исходное представление: True означает исходную пустую строку. Все записи сохранены.

Копия `02_aircraft_reference_enriched.parquet` сохраняет все поля предыдущей копии и добавляет следующие поля только для справочного разбора 23 неоднозначных значений.

| Поле | Тип | Смысл |
| --- | --- | --- |
| `aircraft_description_reference` | string | Производное Description для 18 прямо сопоставленных значений, 5 888 записей. Для остальных записей null. Не является окончательным нормализованным полем всей базы. |
| `aircraft_reference_status` | string | `direct_unique_reference_match` – прямое однозначное справочное соответствие; `unresolved` – одно из пяти неразрешенных значений; `source_description_missing` – исходное описание отсутствует после согласованной нормализации; `not_reviewed` – значение вне текущего разбора. |
| `aircraft_reference_source` | string | URL официальной таблицы ICAO для сопоставленных записей; null для остальных. |
| `aircraft_reference_checked_date` | string | Дата проверки справочного снимка, `2026-10-08`, для сопоставленных записей; null для остальных. Это не дата исторического действия кода. |

Источник – таблица [официального поиска ICAO Doc 8643](https://www.icao.int/operational-safety/doc-8643-aircraft-type-designators/search), публичный endpoint `https://doc8643.icao.int/External/AircraftTypes`, метод POST. SHA256 справочного снимка и рабочей копии сохранены в `reports/preparation/04_aircraft_reference_applied.json`. Историческая применимость в 2019–2023 годах и тип конкретного борта этим сопоставлением не подтверждены. Исходные `typecode` и `icaoaircrafttype` не перезаписаны.

Копия `03_c40_diagnostic_flags.parquet` сохраняет все 28 физических полей предыдущей копии и добавляет три булевых поля без null:

| Поле | Тип | Смысл |
| --- | --- | --- |
| `c40_time_missing` | bool | True при физическом null в `C40_CROSS_TIME`; 1 652 382 записи. Не описывает полноту всей траектории. |
| `c40_after_first_attempt` | bool | True, если C40 строго позже первого элемента `attempt_times`; 87 записей, включая 45 отмеченных уходов. Первый элемент проверен на равенство минимуму списка. |
| `c40_after_landing` | bool | True, если C40 строго позже `landing_time`; 42 записи, все без отмеченного ухода. Это подмножество предыдущего флага. |

Если C40 отсутствует, оба временных флага False: это не означает подтвержденную корректность C40. Сравнения выполняются в UTC, без временного допуска. Временные флаги используют сведения завершенного наблюдения и служат для аудита; их нельзя подавать в модель раннего прогноза. Отбор по ним требует проверки изменения состава выборки. Все прежние значения и строки сохранены; определения и SHA256 находятся в `reports/preparation/07_c40_flags_applied.json`.

По решению пользователя на шаге 04_08 из отдельной копии `04_c40_ambiguous_pairs_excluded.parquet` исключены обе строки 147 неоднозначных пар C40: 294 записи, включая три GoA=True. Новая копия содержит 7 983 960 строк и 26 250 положительных меток. Все 31 физическое поле и значения сохраненных строк неизменны; исходник и копия 03 сохранены целиком. Это исследовательское исключение не доказывает ошибочность каждой удаленной из выборки записи. Прежние диагностические счетчики относятся к копии 03. Журнал: `reports/analytical_sample/04_08_pairs_excluded.json`.


## Выборка эксперимента C40 после 04_10

`europe/data/analytical/04_c40_available.parquet` содержит 6 331 494 строки и 18 358 меток GoA=True, все 31 поле сохранены. Правило: четыре поля C40 заполнены, числовые значения конечны, C40 строго раньше первой попытки. Это проверка доступности, не полная валидация сопоставления или метки. Неполные записи и записи с неподходящим временем C40 исключены из эксперимента; восстановление потребовало бы отдельной затратной проверки траекторий вне текущей задачи.

`europe/data/analytical/04_c40_outside_experiment.parquet` сохраняет остальные 1 652 466 строк и 7 892 положительные метки для аудита. Исходник и предыдущие копии не изменены. Поля исхода и диагностические флаги присутствуют для аудита и не становятся разрешенными входами модели.
