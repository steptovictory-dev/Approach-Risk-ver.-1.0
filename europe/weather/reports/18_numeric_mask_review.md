# 18. Применение правил числового качества

Пользователь принял предложенную маскировку отдельных полей. Создана отдельная
числовая копия `data/numeric_quality_v1/`: 93 файла станция–год, все 6 331 485
строк и 18 349 GoA. Она содержит идентификаторы, исходные сообщения, статусы
сопоставления и проверки, восемь исходных числовых полей и их копии `_model`.
Остальные поля полного погодного набора остаются в `data/full/results/`;
для объединения использовать `source_row` и зафиксированный SHA-256 входа.

В 44 строках модельные значения заменены пропусками; исходные числа сохранены:

| Поле | Числовых ячеек заменено пропуском |
| --- | ---: |
| `temperature_c_model` | 37 |
| `dewpoint_c_model` | 39 |
| `qnh_hpa_model` | 2 |
| `cloud_ceiling_ft_model` | 3 |
| `lowest_known_cloud_base_ft_model` | 3 |
| Всего | 84 |

Маски привязаны к согласованному регистру 18 сообщений. Семь сообщений
этого регистра не связаны с посадками при основном сопоставлении; примененные
маски относятся к связанным строкам. Для новых сообщений превышение точки
росы и выход давления из диагностического интервала требуют повторного аудита:
текущая копия не является универсальным онлайн-детектором качества.

Все затронутые строки имеют статус `matched` при давности до 60 минут,
нулевой предполагаемой задержке и сохранении COR. Среди них нет GoA.
Метка не участвовала в определении масок. Иные сценарии доступности не
подменяются этим результатом.

## Проверки

Каждый сохраненный файл прочитан повторно. Проверены:
- совпадение всех сохраненных исходных полей с соответствующим исходным файлом;
- пропуски только в выбранных модельных ячейках;
- точное совпадение модельных значений вне масок;
- покрытие идентификаторов входа ровно один раз и сохранение обеих меток;
- SHA-256 всех 93 исходных файлов до и после применения;
- SHA-256 аналитического входа до и после применения.

[Ноутбук 10](../notebooks/10_numeric_quality_application.ipynb) выполнен:
код, таблицы, журнал, примеры исходных/модельных значений и рисунок с легендой.
Он повторно проверяет контрольные суммы всех исходных и созданных файлов.

Артефакты: [журнал ячеек](18_numeric_mask_journal.csv),
[воздействие по аэропортам и меткам](18_numeric_mask_coverage.csv),
[сводка полей](18_numeric_mask_fields.csv),
[проверки и контрольные суммы](18_numeric_mask_application.json).

## Ограничения

Числовая копия не готова к обучению без правил доступности, пропусков,
остаточных форматов и временного разделения. Исходные поля не следует
по ошибке использовать вместо `_model`, обходя маски. Производные признаки
нужно рассчитывать по модельным копиям с сохранением зависимых пропусков.
Отсутствие флага не подтверждает физическую достоверность значения.

Импутация, исправление исходных текстов, удаление посадок, обучение и
восстановление по последующим сообщениям не выполнялись. Следующий этап —
отдельный аудит остаточных форматов декодирования.
