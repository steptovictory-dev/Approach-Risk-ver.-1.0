# 04 — Словарь полей погодного пилота

Источник — исходный текст METAR из IEM. Единицы и специальные коды устанавливаются по наблюдаемой части сообщения. [Met Office](https://docs.mavis.metoffice.gov.uk/guidance/metar-decode/) и [CAA CAP 746](https://www.caa.co.uk/publication/download/12602), раздел 4, использованы для семантики кодов; правила пилота не являются эксплуатационными нормативами.

`data/04_decoded_reports.parquet` содержит сообщения; `data/04_pilot_features.parquet` — все записи пилота и их связи с сообщениями. Числа вместе с границами, флаги и исходные строки сохраняются без импутации. Поля со статусом `error` / `needs_review` требуют проверки; их отдельные распознанные значения не считаются утвержденным набором признаков.

## Происхождение и контроль

| Поле | Смысл и роль |
| --- | --- |
| `metar_id` | SHA256 станции, полного времени UTC и исходной строки; идентификатор конкретного сообщения, не предиктор. |
| `station` / `airport` | Код станции / конечного аэропорта записи. Совпадение кодов проверено; известность целевого аэропорта к C40 отдельно не доказана. |
| `metar_utc` | Время наблюдения архива, сверенное с группой DDHHMMZ. Это не подтвержденное время исторического получения. |
| `metar` | Полный исходный текст, без исправления. |
| `archive_month` | Месяц запроса; первые сутки архива могут принадлежать предыдущему месяцу. Только происхождение. |
| `observed_text` | Рабочая копия текста до обозначенного тренда и RMK. Неподдержанные группы могут остаться в ней и отмечаются статусом. |
| `trend_text` | Отделенный прогноз, включая NOSIG. Не используется как наблюдаемая погода. |
| `remarks_text` | Отделенные RMK, не переносимые в основной набор наблюдаемых полей. |
| `unclassified_tail_text` | Группы после QNH, похожие на новые погоду/облака без явного индикатора тренда. Сохраняются, но не добавляются к наблюдаемым явлениям и слоям. |
| `has_trend`, `has_remarks` | Наличие соответствующих частей; контроль структуры, не подтверждение прогнозируемых условий. |
| `correction_reported`, `auto_reported` | В исходной наблюдаемой части явно переданы COR / AUTO. COR не устанавливает время получения исправления. |
| `parser_status` | `ok` — без замечаний в текущем объеме проверок; `error` — строгий python-metar не разобрал структуру; `needs_review` — замечание об отсутствующей/несогласованной группе. Это не независимая метеорологическая валидация. |
| `parser_error`, `decode_issues` | Текст ошибки и перечень причин замечаний, без автоматической очистки исходника. |
| `decoded_candidate` | Диагностический флаг отсутствия замечаний. Не решение об исключении записей и не допуск к реальной эксплуатации. |

## Ветер

| Поле | Единицы и смысл |
| --- | --- |
| `wind_token` | Исходная группа ветра; поддержаны KT, MPS и KMH. Неподдержанная группа не угадывается. |
| `wind_direction_token` | Трехзначный код, VRB либо ///. |
| `wind_direction_deg` | Переданное направление относительно истинного севера, в градусах. При VRB, /// и штиле отсутствует. 360 сохраняется как код севера. Это не направление ВПП и не курс самолета. |
| `wind_unit` | Исходная единица KT / MPS / KMH. |
| `wind_speed_raw`, `wind_gust_raw` | Переданное числовое значение в исходной единице. Для P-кода — граница. |
| `wind_speed_relation`, `wind_gust_relation` | `eq` — переданное значение, `gt` — P-код, `missing` — число неизвестно. Отношение обязательно сохранять при использовании чисел. |
| `wind_speed_kt`, `wind_gust_kt` | Значение / граница в узлах. 1 MPS = 3600/1852 kt, 1 KMH = 1000/1852 kt. |
| `gust_group_reported` | Передана G-группа. False означает отсутствие группы, а не нулевой порыв; G// оставляет числовой порыв неизвестным. |
| `wind_variable` | VRB явно передан; при неизвестном направлении флаг неизвестен. |
| `wind_calm` | Передана 00000 с нулевой скоростью; при неизвестных направлении/скорости флаг неизвестен. |
| `wind_variation_token` | Исходный диапазон вида 330V030, без восстановления промежуточных значений. |
| `wind_variable_from_deg`, `wind_variable_to_deg` | Границы переданного диапазона, градусы истинного севера. Переход через север сохраняется как 330 → 030. |

## Видимость и явления

| Поле | Единицы и смысл |
| --- | --- |
| `visibility_token`, `visibility_unit` | Исходный код prevailing visibility после ветра / диапазона; в этом декодере поддержан европейский метрический формат, включая NDV. SM вне текущего объема поддержки отмечается для проверки. |
| `visibility_m` | Число или граница в метрах. 9999 / CAVOK → 10000 с `ge`; 0000 → 50 с `lt`; //// → пропуск. |
| `visibility_relation` | `eq` — переданный числовой код, `ge` — не менее, `lt` — меньше, `missing` — неизвестно. Значение нельзя интерпретировать без отношения. Обычный код также имеет отчетную дискретность. |
| `cavok` | CAVOK явно передан. Его условия ограничены правилами сообщения; он не исключает все локальные авиационные опасности. |
| `visibility_ndv` | Код NDV явно передан. |
| `present_weather_tokens` | Наблюдаемые коды явлений до температуры/QNH, через пробел. Недавние и прогнозные явления сюда не входят. |
| `present_weather_status` | `reported`, `cavok_no_significant_weather`, `missing_group`, `no_group_reported`. Последнее не означает доказанное отсутствие всех явлений. |
| `recent_weather_tokens` | Переданные RE-коды недавних явлений. Сохраняются отдельно от текущей погоды. |

## Облачность

Высоты — ft относительно аэродрома, без сравнения с минимумами захода. `000` означает ниже 100 ft, а не точные нулевые облака. Обычные высоты сохраняют переданную ступень кода.

| Поле | Смысл |
| --- | --- |
| `cloud_tokens` | Исходные группы слоев, VV, NSC/NCD/SKC/CLR. |
| `cloud_state` | `cavok`, `layers`, явный NSC/NCD/SKC/CLR либо `not_reported`; коды с разным смыслом не объединяются в «ясно». |
| `cloud_layers_json` | Все распознанные группы: количество `cover`, высота/граница `height_ft`, отношение `height_relation`, тип `kind` и исходный `raw`. /// сохраняется как неизвестное. |
| `lowest_known_cloud_base_ft`, `lowest_known_cloud_base_relation` | Минимальная из известных баз / границ слоев, кроме VV. Не заявляет минимум неизвестных слоев. |
| `cloud_ceiling_ft`, `cloud_ceiling_relation` | Минимальная база / граница явно переданных BKN/OVC; число оставляется неизвестным при неизвестной высоте такого слоя либо количестве другого слоя. Использовать только с отношением. |
| `cloud_ceiling_status` | `reported`, `amount_unknown`, `height_missing`, `no_bkn_ovc_group`. Последний не равен отсутствию потолка на бесконечной высоте. |
| `vertical_visibility_ft`, `vertical_visibility_relation` | Число / граница из VV, отдельно от BKN/OVC; VV/// остается пропуском. |
| `vertical_visibility_reported` | VV-группа присутствует, даже если высота неизвестна. |
| `cloud_type_unavailable` | Тип явно неизвестен в суффиксе /// или полной группе пропуска. |
| `cloud_amount_unavailable` | Количество облаков неизвестно, включая //////CB/TCU. |
| `cumulonimbus_reported`, `towering_cumulus_reported` | Явно переданы CB / TCU. False означает, что соответствующий код не передан, и не доказывает отсутствие облака при неизвестном типе. |

## Температура и давление

| Поле | Единицы и смысл |
| --- | --- |
| `temperature_token` | Исходная группа температуры и точки росы. |
| `temperature_c`, `dewpoint_c` | °C; M преобразуется в минус, неизвестное значение сохраняется как пропуск. |
| `qnh_token`, `qnh_unit`, `qnh_raw` | Исходная Q/A-группа, hPa либо inHg и число в этой единице. A2992 → 29.92 inHg. |
| `qnh_hpa` | QNH в hPa. QFE, SLP и иное давление не подставляются. Для A используется 1 inHg = 33.8638866667 hPa. |

## Связи и диагностические сценарии

| Поле | Смысл и роль |
| --- | --- |
| `source_row` | Номер строки конкретного входного Parquet; его SHA256 в журнале. Сохранение кратности, не физическая идентичность рейса. |
| `flight_id`, `icao24` | Исходные идентификаторы, только связи/аудит. |
| `landing_time`, `GoA` | Итоговое время и исходная метка. Не погодные предикторы. |
| `C40_CROSS_TIME` | Момент сопоставления UTC. |
| `month` | Месяц C40, а не месячная погода или будущий агрегат. |
| `age_minutes` | C40 минус время наблюдения; положительное число минут. Не подтвержденная задержка передачи. |
| `ambiguous`, `correction` | Диагностика исходного сопоставления: разные тексты одного времени / COR в выбранном сообщении. |
| `status` | `matched`, `older_than_60min`, `ambiguous`, `missing_or_older_than_90min` — результат присоединения по основному правилу 60 минут. |
| `availability_verified` | False: историческое время доступности сообщения не подтверждено. |
| `weather_candidate_60min` | Однозначный METAR до 60 минут и отсутствие замечаний декодера; осторожный диагностический сценарий. |
| `weather_candidate_60min_without_cor` | Предыдущий сценарий без COR. Это не автоматическое исключение из основной базы. |

Ни одно исходное наблюдение не удалено. Числа погодных эффектов и новая модель в этом этапе не оценивались.
