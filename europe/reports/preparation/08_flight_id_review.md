# Повторяющиеся flight_id – коллизии имен и ключ наблюдения

Шаг 9 ноутбука 03, 08.10.2026. Проверены все 7 984 254 строки последней копии `03_c40_diagnostic_flags.parquet`. Исходник и рабочая копия проверены по SHA256 до и после; данные не изменены.

## Метод проверки

По всему файлу подсчитаны точные значения flight_id; для каждого повторяющегося имени извлечены все записи. Сравнены UTC-даты посадки, ICAO24, аэропорты, позывные, времена, GoA и содержательные поля. Проверены все пары внутри групп. Примеры служат для просмотра; общие выводы получены по всем группам.

Точные дубли проверены по всем полям рабочей копии без служебного `__index_level_0__`, а также по 20 исходным содержательным полям после согласованной нормализации. Сравнение выполнено через каноническое представление значений, без признания одинакового хеша достаточным доказательством. Ключ `landing_time + icao24 + airport` проверен полным аудитом 01 и дополнительно внутри всех повторяющихся имен на этом шаге. Ключевые поля не изменялись при подготовке.

## Первичные источники и границы вывода

[Документация разработчиков traffic, Traffic.assign_id](https://traffic-viz.github.io/api_reference/traffic.core.traffic.html#traffic.core.Traffic.assign_id) описывает имя из позывного и счетчика. [Flight.assign_id](https://traffic-viz.github.io/api_reference/traffic.core.flight.html#traffic.core.Flight.assign_id) показывает шаблон `{self.callsign}_{idx:>03}`. У всех 53 127 рассматриваемых записей часть имени до последнего подчеркивания совпадает с callsign. Однако конкретный алгоритм и версия генератора исторического файла не установлены; сброс счетчика по году или выгрузке остается гипотезой. Документация прочитана через веб-инструмент 08.10.2026.

Сохраненный [ноутбук автора](https://github.com/figuetbe/OSN23-GoA/blob/main/OSN_paper_code.ipynb), SHA256 `2dc1c76cfcc344c35d066ccb4bf4e19d28cafd7bdbe337c3df59f637e01f9f2d`, читает готовый Parquet. В ячейке с индексом 21 времена попыток выбираются по flight_id с `.iloc[0]`. При переносе этого приема на полную таблицу без проверки дат появляется неоднозначность. Корректность исходного отфильтрованного эксперимента этим разбором не оценивается. Нормативное авиационное правило удаления повторов не применяется.

## Последствия для модели и связей

121 группа содержит ровно одну запись GoA=True и другие записи GoA=False. Если гипотетически оставить первую строку каждого flight_id в порядке файла, будут потеряны 29 238 записей, включая 71 запись с отмеченным уходом. Это расчет последствий правила; отфильтрованная база не создавалась.

Нельзя удалять записи, присоединять метки и времена попыток или связывать траектории только по flight_id. Это может перенести сведения между разными датами и бортами. Сам идентификатор и его счетчик не являются признаками модели. Группировка разбиения только по этому имени также не обеспечивает защиту от зависимости наблюдений одного борта.

В текущем файле сочетание `flight_id + UTC-дата посадки` уникально. Это свойство конкретной версии, а не гарантия новых выгрузок. Для присоединения траекторий нужен контекст аэропорта, ICAO24 и точных времен; дата посадки может отличаться от даты начала траектории около полуночи.

Ключ `landing_time + icao24 + airport` уникален в текущем аудите и остается неизменным. Это ключ наблюдения таблицы, а не доказательство идентичности физического полета или точности времени касания. При необходимости отдельный служебный record_id можно связать с версией неизмененного источника и позицией строки; одна позиция без версии файла не является устойчивым идентификатором.

## Решение и воспроизведение

Все записи сохраняем; flight_id не переписываем. Новый record_id, дополнительные флаги и правила объединения на этом шаге не добавлены. Следующий диагностический разбор – число попыток, без автоматического отнесения необычных записей к ошибкам или учебным полетам.
