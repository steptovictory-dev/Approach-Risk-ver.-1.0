# Региональные выборки перед очисткой

Скрипт: `python split_regional_data.py` из корня проекта.
Исходник: `data/raw/go_arounds_augmented.csv.gz`.
Результаты: `data/regional/north_america.csv` и `data/regional/europe.csv`.
Файлы и отчет `split_summary.json` исключены из Git вместе с папкой `data`.
Повторный запуск отказывается перезаписывать существующие результаты.

## Правило отбора

Используем `airport_country`, а не ошибочное `airport_region`.
По [ООН M49](https://unstats.un.org/unsd/methodology/M49) Северная Америка
включает Northern America, Центральную Америку и Карибские территории.
Из присутствующих в наборе кодов выбраны USA, CAN, MEX, BHS, ABW, BES.

Для Европы выбраны присутствующие коды AUT, BEL, BGR, BLR, CHE, DEU,
DNK, ESP, FRA, GBR, ISL, ITA, NLD, NOR, RUS, SWE, UKR.
Отбор России здесь является географическим правилом по стране;
локальные аэропорты ULLI и UUEE находятся в европейской части.

Остальные регионы не включены в эти два файла, но сохранены в исходнике.
Исходное поле `airport_region` остается неизменным, даже если его значение
расходится с нашим географическим отбором.

## Что сохраняется

Все 31 поле, порядок записей внутри региона, строковые значения и пустые
поля. Числа не переводятся в другие единицы, аномалии не исправляются,
строки с пропусками не удаляются. CSV сериализуется заново: вид кавычек
и окончания строк могут отличаться от сжатого исходника.

Проверяются схема, состав стран и число записей при повторном чтении файлов.
Хеши последовательностей строк сравниваются с отобранными исходными значениями.
Региональные выборки еще не являются очищенными обучающими данными.
Правила METAR, давления и очистки выбираем по официальным документам
для конкретной страны и периода, а не по имени регионального файла.
